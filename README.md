# OpenDoors WordPress

Это полный снимок WordPress-сайта OpenDoors, а не только отдельная тема. В репозитории находятся WordPress 7.1, дочерняя тема Blocksy с Timber/Twig, набор коммерческих и публичных плагинов, медиатека и сжатый экспорт MySQL 8.0.41.

## Состав

- WordPress 7.1 и PHP 8.3/Apache в Docker;
- тема `blocksy-child`, наследующая `blocksy`, с `timber/timber ^2.1`;
- MySQL 8.0.41, таблицы с префиксом `wp_opendoors_`;
- Redis Object Cache 3.0.0 с нативным PHP Redis 6.3.0;
- актуальный экспорт `opendoors.sql.gz`, который импортируется при первом создании тома БД;
- отдельные Compose-конфигурации для разработки и production.

В дампе активны, но отсутствуют в `wp-content/plugins`: `imagify`, `wp-migrate-db-pro` и `wp-rocket`. Их нужно вернуть из корректных дистрибутивов/лицензий, если этот функционал необходим. Redis-плагин и его `object-cache.php` уже входят в проект и включаются автоматически. Каталог `wp-content/uploads` хранится через Git LFS и исключён из Docker-образа; обе Compose-конфигурации монтируют его с хоста.

Медиатека и экспорт базы хранятся в Git LFS. На машине, где клонируется репозиторий, должен быть установлен Git LFS; после клонирования выполните `git lfs pull`, чтобы получить сами файлы вместо файлов-указателей.

## Локальный запуск

Для текущей рабочей копии `.env` уже создан с локальными паролями и salt-значениями. Для новой копии проекта:

```powershell
Copy-Item .env.sample .env
```

После этого замените пароли и WordPress salts в `.env`, затем запустите:

После `git lfs pull` экспорт базы будет доступен как `opendoors.sql.gz`. Другой путь можно указать через `DB_SEED_FILE`. Файл `.env` намеренно не отслеживается Git.

```powershell
docker compose up -d --build
docker compose logs -f db
```

Первый импорт большого дампа может занять десятки минут: одна из таблиц SearchWP Metrics содержит около 5 млн строк и требует длительного построения индексов. Когда контейнеры станут healthy, сайт будет доступен на <http://localhost:8080> (порт задаётся через `DEV_PORT`). Исходники примонтированы в контейнер, поэтому локальные изменения видны сразу.

Дамп выполняется только на пустой БД. Чтобы намеренно пересоздать локальную БД с нуля, остановите проект и удалите его тома командой `docker compose down -v`, затем снова выполните `docker compose up -d`. Эта команда необратимо удаляет локальную БД и Redis-данные.

## Production

Перед запуском production обязательно:

1. Задайте в `.env` длинные уникальные `DB_PASSWORD`, `DB_ROOT_PASSWORD` и восемь WordPress key/salt.
2. Проверьте `PROD_WP_URL` и `RECOVERY_MODE_EMAIL`.
3. Выполните `git lfs pull`, чтобы загрузить `opendoors.sql.gz` и медиатеку, либо используйте уже инициализированный том MySQL.
4. Восстановите недостающие лицензированные плагины.
5. Настройте резервное копирование томов MySQL и uploads.

Запуск:

```powershell
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
```

Эта команда собирает образ с production-настройками OPcache и PHP Redis, поднимает MySQL и Redis, подключает объектный кеш и запускает cron. Дополнительная ручная активация кеша не требуется. Максимальный объём Redis задаётся через `REDIS_MAXMEMORY` и по умолчанию равен 256 МБ.

Production-порт по умолчанию слушает только `127.0.0.1:8080`. Перед ним должен стоять TLS reverse proxy (Nginx, Caddy, Traefik или балансировщик), который передаёт как минимум `Host` и `X-Forwarded-Proto`. База и Redis не публикуются наружу. Код темы, плагинов и ядра входит в образ; постоянными являются БД, Redis и каталог `wp-content/uploads`, смонтированный с хоста. WordPress cron запускается через прогретый Apache отдельным контейнером раз в минуту. Healthcheck проверяет PHP и соединение с MySQL без полной загрузки WordPress.

Для первого запуска на чистой production-инфраструктуре экспорт импортируется из файла, указанного в `DB_SEED_FILE`. На уже инициализированном томе он повторно не выполняется. Репозиторий публичный, поэтому при обновлении экспорта учитывайте, что содержащиеся в нём данные будут доступны всем. Файл `.env` не должен попадать в систему контроля версий.

## Полезные команды

```powershell
# Статус dev
docker compose ps

# Логи WordPress
docker compose logs -f wordpress

# Проверка итоговой конфигурации
docker compose config --quiet
docker compose -f docker-compose.prod.yml config --quiet

# Остановка без удаления данных
docker compose down
```
